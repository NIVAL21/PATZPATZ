# פצפץ — שרת ולוגיקת משחק

פוקר PLO וירטואלי עם 3 בורדים נפרדים ובחירת קלפים נפרדת לכל בורד.

## מה יש כאן

```
src/
  cards.js          חפיסה, ערבוב, המרה בין קלף לאובייקט/מחרוזת
  handEvaluator.js  דירוג יד 5 קלפים + בחירת היד הטובה ביותר ב-PLO (2 מהיד + 3 מהבורד)
  payout.js         חישוב תשלומים זוגי בין כל שני שחקנים, כולל ספליט וסוויפ
  gameEngine.js      state machine מלאה: הצטרפות -> חלוקה -> הגשת splits -> נעילה -> חשיפה -> תוצאה
server.js            עטיפת Socket.io סביב gameEngine
test/                18 בדיקות אוטומטיות
```

## מה נבדק בפועל (ורץ בהצלחה — 18/18)

`src/*` ו-`gameEngine.js` הם קוד טהור בלי תלות ברשת, ונבדקו קצה-לקצה כולל:
- כל הדוגמאות המספריות מהדרישות המקוריות (10/20/60/120, ספליט=0 בין שני מנצחים)
- מקרי קצה במעריך הידיים: wheel (A-2-3-4-5), פול-האוס מול פלאש, PLO שמאלץ בדיוק 2 מהיד + 3 מהבורד
- אימות חלוקה: לא ניתן קלף כפול, לא ניתן קלף שלא שייך לשחקן, לא ניתן לשנות אחרי נעילה
- שהמידע החבוי (טרן/ריבר, קלפי יריבים) לא נחשף ללקוח לפני שכל השחקנים ננעלו
- שסכום הרווח/הפסד של כל השחקנים ביד תמיד מתאפס (invariant של משחק zero-sum)

הרצה: `npm test`

## מה לא נבדק בפועל

**`server.js` לא רץ בסביבה שבה נבנה** — אין גישת רשת להתקין את `socket.io`. הקוד כתוב ומוכן, אבל הוא רק שכבת wiring דקה (~90 שורות) שקוראת לפונקציות שכבר נבדקו ב-`gameEngine.js`, כך שהסיכון בו נמוך יחסית. לפני שסומכים עליו במשחק אמיתי:

1. `npm install` במחשב עם גישת רשת
2. `npm start` (מאזין על פורט 3000)
3. לבדוק ידנית עם 2-3 חלונות/מכשירים לפחות יד אחת מלאה

## מה עוד חסר לגרסה ראשונה משחקית

- **אימות שחקנים** — כרגע `playerId`/`name` מגיעים מהלקוח בלי בדיקה. מספיק ל-5 חברים, אבל שווה guard בסיסי (למשל קוד חדר + שם, בלי אימות אמיתי).
- **ניקוי חדרים ישנים** — חדרים נשארים בזיכרון לתמיד כרגע. לא קריטי בהיקף כזה, אבל שרת שרץ הרבה זמן יצבור חדרים מתים.
- **יד הבאה** — כרגע יש לוגיקה ליד אחת בלבד (`waiting -> dealt -> revealed`). להוסיף מעבר `revealed -> dealt` (יד חדשה) ומעקב אחרי יתרות מצטברות בין ידיים.
- **לקוח מובייל (React Native)** — עדיין לא נבנה בכלל. הפרוטוקול מוגדר בבירור דרך אירועי ה-socket (`create_room`, `join_room`, `start_hand`, `submit_split`, ואירוע `room_state` שמגיע בחזרה), כך שאפשר לבנות אותו בנפרד מול הפרוטוקול הזה.
